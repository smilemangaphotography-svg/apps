# ShishaLove Mobile 1.1.1

Production mobile wrappers for the live ShishaLove WordPress/WooCommerce platform.

## Canonical release branch

`shishalove-main`

WordPress/WooCommerce remains the single source of truth for products, categories, stock, prices, orders, customer data and merchant writes. The mobile apps never maintain an independent catalogue.

## Android

- **ShishaLove Customer** — `eu.shishalove.customer` — version `1.1.1` / build `111`
  - opens `https://shishalove.eu/shishalove-app/?app=android&build=111`
  - Android 15/targetSdk 35 system-bar inset protection keeps the header and bottom navigation out of the status/navigation areas
  - native phone-polish guard removes internal release badges and repairs common WordPress lazy-image fallbacks
  - persistent cookies/cart/account session
  - internal ShishaLove links stay in-app; external links open in the system browser
- **ShishaLove Merchant** — `eu.shishalove.merchant` — version `1.1.0` / build `110`
  - opens the canonical ShishaLove merchant runtime
  - WordPress login/wp-admin remain in the same WebView so authentication persists
  - image/file-library upload support

The release workflow validates both Android apps. Store signing is intentionally not committed to the public repository. Configure a private Android release keystore before Play Store publication. Development/install APKs can still be generated by CI for device testing.

## iPhone / iOS

Native iOS Customer and Merchant wrappers live under `shishalove-ios/` and use `WKWebView` with the same live WordPress/WooCommerce backend and cookie/session model.

- Customer bundle ID: `eu.shishalove.customer` — version `1.1.1` / build `111`
- Merchant bundle ID: `eu.shishalove.merchant` — version `1.1.0` / build `110`
- minimum deployment target: iOS 16

The Customer wrapper points at the Bridge 1.1.1 runtime and includes the same release-badge/lazy-image defensive polish. iOS safe-area adjustment remains native through `WKWebView`/SwiftUI.

The iOS project can be generated with XcodeGen using `shishalove-ios/project.yml`. CI performs an unsigned simulator build to catch compilation problems. Installing on physical iPhones or distributing through TestFlight/App Store requires an Apple Developer team, signing certificate and provisioning profile; those credentials must remain private and are not stored in GitHub.

Until native iOS signing is configured, both live web apps can also be installed immediately on iPhone from Safari using **Share → Add to Home Screen**.

## WordPress bridge

The canonical customer runtime is **ShishaLove WordPress Bridge 1.1.1**. Its contract and design lock live under `shishalove-wordpress-bridge/`. Bridge 1.1.1 must be deployed in WordPress for the full server-side phone-polish changes, category imagery and app-shell fixes to be served to installed clients.
